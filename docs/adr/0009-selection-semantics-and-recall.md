# ADR-0009：测试选择语义与召回度量——加法起步、减法门控

- 状态：Accepted
- 日期：2026-09-16
- 决策人：Owner（grill-with-docs 审核会话）
- 关联：ADR-0002、ADR-0006、ADR-0007、ADR-0008；收敛审核遗留问题第 4 项

## 背景

V0.2 提案的核心主张是"不跑全部测试，只跑最可能受影响的"。但选择的漏检 = 回归流向 main。V1 图谱已收敛为模块粒度 + 保守回退（ADR-0007），"少跑"的空间只剩两处：CI 内 unit/api 子集选择、一次性栈上的 E2E 场景选择。**度量义务只跟"减法"走："加法"（多跑、升级）没有漏测风险。**

## 决策

### 1. 加法起步，减法默认关

- unit/api 在项目 CI **永远全量跑**；影响集/风险只用于升级：追加 e2e 类别、提升风险档、丰富 Planner 上下文。
- E2E 场景选择（减法）是 feature flag，**默认关**，registry 项目级声明；开启受第 3 条门槛约束。
- 提案的 Level 0～5 分层在 V1 的落位：lint/static/unit/api = CI 常跑；e2e = qualityPolicy + 升级；夜间全量 = 兜底；performance/security 后续。

### 2. 校准协议：历史回放 + 在线对照

- **离线回放**：收集试点仓库历史 merged PR 与事后真实失败/REOPEN 案例，重放选择算法计算漏检。
- **在线对照**：夜间全量与 PR 子集的差异即漏检信号。
- 预埋回归仅作一次性冒烟校准、单独标记，**永不计入 VAL 价值或可靠性样本**（对齐 VAL-02"预埋 Bug 不计入"纪律）。

### 3. 指标与断路器（代码安全轨）

- 指标：**选择召回率**（被选中测试捕获的真实回归 / 全部真实回归，"全部"由夜间全量或事后 REOPEN 定义）+ 节省时长。
- 启用减法的前置：最近连续 N 次全量对照召回 = **100%**（N 为 registry 项目配置，默认值代码固定）。
- **断路器**：任一漏检（PR 子集绿但夜间全量挂，或事后 REOPEN 溯源到被跳过的测试）→ 该项目自动降级为全量选择、落审计并通知；重新启用需 Owner 复核并记录。降级不可被配置绕过。

### 4. 夜间兜底：项目 CI scheduled

试点仓库自带 scheduled workflow 跑全量套件（CI 内可拉 compose 栈），结果按既有签名与证据链回流；ForgeOps 不背算力，与 ADR-0004 CI 通道同构。

**证据绑定扩展**：scheduled 事实无 PR number，绑定 `repo + branch + commit + workflow`，与 PR Check Run 同级核验（Inbox/归一化需支持该事实形态，属 DEL 边界的受控扩展）。

## 影响

- 减法上线时间由校准数据决定，**可能长期保持关闭——这是可接受结果**：验证层 V1 的价值在门禁、证据与风险升级，"省测试时间"让位于安全语义。
- 符号级图谱升级（ADR-0007 延后项）是让减法有意义的精度路径：模块粒度下 E2E 场景选择的召回天然受限。
- 验收清单新增 `VER-24`～`VER-26`。
- 召回数据与断路器事件计入 OPS-10 指标。
