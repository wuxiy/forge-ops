# ADR-0010：验证证据的 LLM 输入边界、存储与保留

- 状态：Accepted
- 日期：2026-09-16
- 决策人：Owner（grill-with-docs 审核会话）
- 关联：ADR-0003（Multica 通道）、ADR-0006（qualityPolicy.evidenceRetention）、ADR-0008（一次性栈与种子）；细化 `VER-17`；收敛审核遗留问题第 7 项（证据/PII）

## 背景

验证证据含截图、trace、日志等可能携带业务数据的产物（政务/HIS 语境敏感），而 Failure Triage 天然需要看截图定位 UI 失败。2.0 纪律要求已知敏感数据外发 0 次（SEC-06/SEC-12）。同时大件证据的存储膨胀与保留清理机制未定。

## 决策

### 1. LLM 输入白名单（数据不出域的两条硬前提）

验证侧 LLM（Planner / Failure Triage）只接受：

- 经既有清理链（ContextPreparation 同源纪律）脱敏的**文本摘要**（结构化结果、日志摘要）；
- **截图**（多模态定位 UI 失败）。

截图进 LLM 的两个前提，均为验收项：

1. **种子合成纪律**：一次性栈种子只含合成数据（ADR-0008 的栈隔离使截图天然无真实 PII）；
2. **可信域模型**：Multica 通道的模型端点必须部署在内网 allowlist 域内，禁止出公网调用外部 LLM API（写入试点接入清单）。

**不进 LLM**：trace、视频、原始 HTTP payload、原始日志原文。

### 2. 存储：文件目录 + DB 引用

- 大件（trace/截图）存文件目录（部署环境提供、按项目隔离），DB 存引用路径与内容哈希；
- V1 采集 trace + 截图，**不采集 video**（trace 足够定位，video 体积大且 PII 面更大）；
- 对象存储（MinIO/S3）为后续评估项。

### 3. 保留与清理

- 保留期：`qualityPolicy.evidenceRetention` 单值（ADR-0006），到期由定时清理任务删除大件；
- 清理动作留审计；**摘要行（结果、结论、哈希）永久保留**——证据链可追溯性不随内容清理而断裂。

## 影响

- 验收：`VER-17` 收紧（种子注入敏感样本 + 清理审计）；新增 `VER-27`（LLM 输入边界负向 + 模型端点域内验证）。
- 试点接入清单新增：Multica 通道模型端点的可信域声明与验证。
- 执行器需在采集时即过滤 video 配置，避免先采后删。
