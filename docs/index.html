Engineering Loop

一条可追踪的完整闭环

不追求"无人值守自动修复"。AI 负责重活（重现、找日志、定位、改码），人类保留关键节点（Review、合并、发布）。

01 · HUMAN
业务页面提交反馈
Vue SDK 白名单采集：失败请求、Request ID、前后端版本 / Commit、Console 错误，一键提交。
02 · FORGEOPS
Context Pack 自动构建
Gateway 按 requestId 拉取日志摘录、关联 Repo 与版本，PII 双重脱敏后生成标准化上下文。
03 · AGENT
Triage 根因分析
Triage Agent 只读分析：定位到文件与行号、引用日志证据，判定是否进入自动修复。
04 · AGENT
Coding 修复 + Draft PR
Coding Agent 切 feature/agent/FB-xxxx 分支，修复 + 测试全绿后全自动创建 Draft PR。
05 · HUMAN
人工 Review 合并
开发者 Review 六段式 PR 报告（问题/根因/修改/测试/风险/来源），一键合并。
06 · CI/CD
复用现有流水线
Git / CI / 部署三回调驱动状态机：BUILDING → DEPLOYING，幂等且可审计。
07 · 通知
部署完成自动通知原反馈人「待验证」，附带版本号 —— 不再需要人工找人。
08 · HUMAN
原反馈人验证
SDK 内一键「验证通过 / 仍有问题」；Reopen 复用原 Issue 并追加上下文，禁止孤立新 Bug。
⛨ Human Gate：Agent 自动化终点是 Draft PR。Merge 与发布永远人工 —— 平台侧硬编码，Agent 冒充 merge 的回调会被直接拒绝（已实测）。
Why ForgeOps

开发者的时间去哪了？

测试环境的问题处理，大量时间耗在"不是写代码"的环节。ForgeOps 逐项拆掉：

🔁上下文重复整理

问题描述、版本、页面、日志、代码信息需要开发二次收集。

→ Context Pack 自动构建，requestId 直查日志
📉信息传递损耗

线上文档、群聊、口头沟通之间细节丢失。

→ 反馈即结构化数据，全链路一个 ID 追踪
🧲开发被动中转

重现、查日志、整理 Prompt 给 AI，占据主要工时。

→ Triage / Coding Agent 直接消费标准化上下文
🔓闭环不完整

发布后仍需人工找原反馈人，Issue 状态难追踪。

→ 部署回调自动通知，验证结果回写同一时间线
Architecture

只造必须造的，其余复用

公司长期资产是 Registry、Policy、Context Pack 与反馈闭环；Agent 编排交给 Multica，执行交给 Claude Code，Git 与 CI/CD 原样复用。

能力选型定位
反馈采集自研 ForgeOps Feedback SDK（Vue 3）白名单采集 · 我的反馈 · 验证入口
工程接入层自研 ForgeOps Gateway（Spring Boot 4）Intake · Context Pack · 状态机 · 回调 · 审计
项目接入自研 Project Registry新项目 = 一份 YAML，平台零改动
Agent 编排复用 Multica（self-host v0.4.26）Issue · Agent · Skill · Runtime · 看板
Coding Agent复用 Claude Code本地 daemon 执行，SSH scoped 凭据
Git / CI/CD复用 现有平台三回调契约接入，不重建发布系统
异常治理 / SRE RCAV0.2+ Keep / HolmesGPT自动错误发现与根因调查，延后引入

Quick Start

三步跑起来

bash
# 1. 本地运行（demo 前后端 + Gateway）
$ pnpm install
$ cd examples/demo-app/api  && mvn spring-boot:run      # :8081
$ cd examples/demo-app/web && pnpm dev                 # :5173（含反馈入口）
$ cd gateway/forgeops-gateway && mvn spring-boot:run        # :8080

# 2. 真实 Vue 项目接入 SDK（≤5 步）
$ pnpm add @forgeops/feedback-vue
// main.ts: createForgeOps({ gatewayUrl, projectId, environment: 'test' })

# 3. 新项目接入平台 = 一份 YAML
$ cp registry/projects/demo-app.yaml registry/projects/your-app.yaml
$ curl -X POST gateway:8080/api/v1/projects/reload

完整接入指南（Request-ID 链路 / CI 回调契约）见仓库 docs/integration-guide.md，架构决策见 architecture-v0.1.md。
